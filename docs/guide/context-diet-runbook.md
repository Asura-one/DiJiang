# 上下文瘦身 Runbook（Context Diet）

> 每轮对话都注入的内容是稀缺资源。本 runbook 用于模型升级/上下文成本变化时对 agent 指令层重跑一次瘦身审计。
> 首跑：2026-11-18，实测数据见文末基线。

## 何时跑

换新模型、skill 数明显增长、或发现 agent 开始复读无效指令时。

## 流程（13 步）

### 1. 盘点分层
量化两类内容的字符数：**每轮注入层**（根 AGENTS.md、CLAUDE.md、全局规则、无 `paths:` 的 rules、每个 skill 的 frontmatter description）与**按需加载层**（SKILL.md 正文、references、docs）。
臃肿多半不是写多了，是**放错了层**。

### 2. 分类出清单
逐段标 修/删/挪/改写/保留；挪的写明目的地；每条附一句原因。**清单先给用户确认再动手**。

### 3. 逐句行为判断
"先读再改/跑测试/注意边界"这类本来就会做的不删白不删——**删**。拿不准先保留。

### 4. 目标导向
写**目标**（做完什么样、怎么算完成、要什么证据），少写路线。步骤删掉后还能换条路达成同样结果就删；只有**顺序本身是约束**才留（先验证再发布、先确认再删除）。

### 5. 重复合并
同一要求说了三遍 → 换成一个 agent 本来就懂的词（tight、报告腔）。口号换成形象词，配一组 NO/OK 例子。

### 6. 内容归位
需要判断的进 skill；同样输入总出同样输出的改成脚本或 hook；项目命令/发布步骤进项目指南；**跨项目硬约束才进全局规则**；"做 Y 前先读 X" 改成"做 Y 时由 hook 注入 X"。

### 7. 描述三要素
skill 的 description 只写 做什么/什么时候用/**不用于什么**；近义词进触发词或 when_to_use；部分场景的内容进 references。
删技能前看**真实调用记录**，不要只 grep 名字；待删清单先展示。

### 8. 保护清单（永不动）
用户偏好、被否掉的方案+原因、机器环境；不报错的坑与"看着像出错其实正常"；"不上传"类半句约束；不可逆操作规则（删数据/花钱/发布/提权/改写已推送历史）；带日期的拍板决策记录。

### 9. 先移后压
内容先整行搬到按需加载层，再压缩；**不要边搬边改写**；不可逆规则原样整段搬。

### 10. 落位技巧
提交/发布/回复/删除类常触发规则留根目录；挪进 docs/ 的在根目录留一句何时去读；根目录避免同时放 CLAUDE.md（Claude Code 有了它就跳过 AGENTS.md）；项目里重复全局规则的句子，只有"所有在用工具都读全局规则"时才删。

### 11. 改后自查
`paths:` 的 glob 都要能匹配到真实文件；grep 拆走的旧文件名；列出所有消失的行，每行都要对得上用户确认过的删除清单。

### 12. 独立复查
交给**没参与精简的 agent**：只给它消失的行和仓库，不给结论；让它搜关键名词（非整句）；哪都找不到的，原样恢复。

### 13. 加载验证
移动的内容要验证真的会被加载：在新位置埋一个暗号，开新会话，先读匹配文件问暗号，再读不匹配文件做反向对照。

## 本仓硬约束（实测踩坑）

- **触发词是路由锚点**：`verify_skills.py` 的 jaccard 重叠检测直接从 description 提取触发词，且注入层路由靠它——触发词不能从 description 挪走，能删的只有重复的英文 "Use when" 从句。
- 改 description 契约必须同步：`scripts/verify_skills.py`（check_description）、`dj-meta/references/skill-template.md`、突变测试夹具。
- 校验基线：`python3 scripts/verify_skills.py` 全库 + `python3 tests/test_verify_skills.py` 必须双绿。
