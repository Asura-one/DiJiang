# pstack 融合批实用指南（v2.5.0）

> 你不需要记任何技能名——所有能力经 dj-ask 按你说的话自动路由。本指南只回答三件事：**说什么、会发生什么、什么时候值得说**。

## 30 秒速查

| 你说 | 得到 |
|---|---|
| "这任务你看着办，留好轨迹" | 决策日志 + 收尾 Attention 风险清单 |
| "别老犯这错"（同类第二次起） | 仓库结构层修复，让这类错写不出来 |
| "给这项目做个验证技能" | 一次生成可复用验证资产 + 功能地图 |
| （什么都不说，正常派活） | 任务开头自动回述目标 + 最小改动，即述即干 |

## 1. 无人值守留轨迹（dj-decision）

**什么时候说**：你要离开电脑的长任务（习惯上半小时一轮监控也适用）、跨多阶段的大活、回头要审查结果的活。

**怎么说**："这个任务你看着办，全程留决策轨迹" / "无人值守跑，回头我检查" / "长期任务，决策都记下来"

**会发生什么**：
1. 任务目录建 `decisions.tsv`，每行：时间 / 阶段 / 决策 / 为什么 / 证据（commit、`file:line`、产物路径——指针不是散文）/ 结果
2. 只记决策点：分叉选择、单元完成、回滚、阻塞——不是流水账
3. 收尾前：日志逐行对照实际过程审计（错行补覆盖行，不改历史），再派**另一个模型**的子代理扫风险
4. 回复末尾给你 **Attention 段**：弱证据决策、跳过的验证、事后看冒险的选择，逐条点名

**回来看什么**：先看 Attention 段，再翻 decisions.tsv（终端 `column -s$'\t' -t decisions.tsv` 直接成表）。

**分寸**：默认不提交 git；只有大到需要轨迹才信的任务才提交。琐碎任务别用（会刷屏）。

## 2. 纠正防复发（dj-correct）

**什么时候说**：你发现自己在纠正同一类错第二次的时候；dj-hunt 修完一个 bug 隐约觉得"这类还会再犯"的时候。

**怎么说**："这个错已经第二次了，别再犯" / "防复发，让它根本写不出来"

**会发生什么**：
1. 翻近期 commits/reverts/评审/你的纠正，把错误**归类**（同类第二次才算类别，单次是噪音）
2. 从最高强制层往下试：**架构消除**（让错误 import 都不成立）→ **类型强制**（坏状态写不出来）→ **lint/CI**（错误信息点名正确写法）→ **行为测试** → 文档规则（只留判断类）
3. 每个新检查**拿真实历史错误跑给你看**——证明它真的会拦住
4. 在 agent 指令文件维护"规则 ↔ 由什么强制"对照表；规则存在却无强制 = 复发，当场升级

**产出**：一类错一个 commit 的结构修复，比"下次注意"硬得多。

**分寸**：单次失误走 dj-hunt 修就行，别小题大做。

## 3. 验证技能生成（dj-verify）

**什么时候说**：一个要反复回归的项目（御界、pentest-core 这类），厌倦每次全量测试都从零摸一遍的时候。

**怎么说**："给 perimeter 做个验证技能" / "建个功能地图，后续回归直接用"

**会发生什么**：
1. 只问代码里看不到的问题，其余自己摸清：怎么启动（含就绪判据）/ 怎么程序化驱动 / 能抓什么证据 / 能不能双开
2. 生成 `.verify/<app>/SKILL.md` 五段：**Launch**（启动+就绪判据+teardown）/ **Doctor**（只读健康检查）/ **Drive**（真实选择器，不是示例）/ **Evidence**（走真实用户路径，抓动作+结果态）/ **Cleanup**（按句柄杀，证据永不清理）
3. 生成 features/ 地图：每个用户功能一个文件（怎么到、怎么驱动、什么状态算工作、坑在哪）
4. **自己端到端跑通一遍才交付**——跑不通只算草稿

**之后**：说"全量回归"时 dj-fullstack-testing 直接吃这张地图；功能变了说"文档对账"（dj-gov）同步。

**分寸**：一次性投入大，值得做的判据 = 你预计要回归 ≥3 次的项目。

## 4. 回述即开工（无需你说任何话）

v2.5.0 起每个清晰任务开工前，回复第一段用大白话复述：你要解决什么问题 + 预期什么最小改动，然后**直接开工不等确认**。方向不对当场打断——这就是它的用途（3 秒防跑偏），不用等它问也不用批准。需求真不清楚才升级 dj-grill 逐轮拷问；分界写死，两个机制不打架。

## 5. 老触发词，新机制

| 照旧说 | 多了什么 |
|---|---|
| "全量回归 / 全面测试" | 性能数字**强制过七问**：限制器 / 两边调平 / 物理极限 / 错误数 / ≥5 次复现 / 端到端占比 / 工作真的发生。说不清限制器或没验错误 → 结论只能写 inconclusive，"快了 30%"这种糊涂账出局 |
| "多方案对比下" / "让几个 agent 竞争"（大事才值得） | arena：N 个候选并行产出 → 跨 agent 交叉评审 → 选基座（维护者最能扩展的）→ 落选者亮点手工嫁接。评分规则先定死不许事后改；候选大分歧 = 需求没写清，回炉重跑不平均 |
| "总结经验 / 沉淀技能" | 大 session 三透镜并行评审（判断力/工具链/发散）找候选；能被 lint/CI/类型强制的经验**优先升机制层**（走 dj-correct），不再一股脑塞 skill 文本 |

## 6. 不用操心的

- **7 条真缺口原则**（Attack the Premise 等）：挂账在 `docs/references/principles-glossary.md`，按纪律等第二次复现才提候选——不是忘了
- **"永不等人类"没融**：与你的确认红线（破坏性操作必须停）冲突，明确不采纳
- **三个新技能名**：记不住就记不住，dj-ask 会路由
