# API 接口文档最小结构（示例优先）

> 摘要：写接口文档的六段最小模板，唯一质量判据是「复制粘贴就能跑通」。dj-output 产出 API 文档、dj-gov 审查文档时引用。

## 原则

示例优先：先给能跑的，再给解释的。读者是开着的终端，不是语文老师。

质量判据只有一条：**新人复制请求示例，一分钟内得到与响应示例一致的结果。**

## 六段结构

1. **一句话说明**：接口干什么、什么时候用（不写「本接口用于…」的废话）
2. **请求示例**：可直接复制的完整请求——真实可达的 base path、方法、头、体
3. **参数表**：`参数 | 位置 | 类型 | 必填 | 说明`——说明列写约束与默认值，不复读类型
4. **响应示例**：真实响应原文（成功 + 至少一个典型错误）
5. **字段表**：只解释响应示例中出现的字段；嵌套用路径记法（`data.items[].id`）
6. **错误码表**：`码 | 含义 | 什么时候出现 | 客户端该怎么办`

## 反模式

- 只有参数表没有可跑示例（读者逆向猜格式）
- 字段表解释从未出现的字段（幽灵文档）
- 错误码只写「系统错误」（无行动指引）
- 示例 base path 是 `localhost:8080`，真实部署在别处
