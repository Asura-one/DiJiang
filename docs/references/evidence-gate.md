# 统一证据门：三层阶梯、强弱验证与假完成形态

> 摘要：dj-check / dj-audit / dijiang-finish-work / dj-loop 共用的「什么才算确认」权威定义：三层证据阶梯、强/软验证分层、结论三态、假完成形态清单。

## 核心问题

两态判定（通过/不通过、疑似/确认）会漏掉中间层：**可达 ≠ 有害 ≠ 可复现**。接口返回 200 不等于行为正确；测试全绿不等于改动正确。第三层证据到位之前，结论最多是「未证实」。

## 三层证据阶梯

| 层 | 名称 | 证明什么 | 典型证据 | 允许的结论措辞 |
|----|------|---------|---------|--------------|
| L1 | 可达 | 能摸到 | 构建/启动跑通、接口有响应、文件存在 | 「可达」「已复现现象」 |
| L2 | 真实影响 | 有没有坏处 | 行为违背规格、数据错误、越权、回归 | 「疑似缺陷，待复现」 |
| L3 | 可复现证据 | 别人也能看见 | 可重复命令 + 断言 + 复现步骤 | 「确认」——只有这层允许 |

审出的问题与交付的验收共用这把尺：`dj-audit` 的发现分级、`dj-check` 的结论措辞、`dijiang-finish-work` 的 confirmed 表述，都以此阶梯到达层为准。

## 强验证 vs 软验证

- **强验证**：可重复命令、退出码、断言——不依赖人也不依赖模型判断。
- **软验证**：人审、LLM 评审、抽查——受疲劳与叙事影响。
- 设计原则：**拿掉这道 gate，执行者还能自判完成吗？** 能 = 软门（效率优化）；不能 = 硬门（正确性依赖，缺它不许上线）。
- 完成判定至少一道强验证；全软验证堆出的「完成」是叙事不是证据。

## 结论三态

最终验收结论强制三选一，**「证据不足」是合法结论，不是失败**：

1. **观测到**（verified）——L3 证据在手
2. **未观测**（not run）——没测 + 原因
3. **证据不足**（inconclusive）——测了但无法判定：样本不足、覆盖盲区、结果矛盾。如实写「证据不足」优于硬凑通过。

## 假完成形态清单（命中即降级）

| # | 形态 | 破法 |
|---|------|------|
| 1 | 测试绿但未覆盖改动的新行为 | 对照 diff 找覆盖盲区；无覆盖走 JiT 探针（`dj-regression-guard/references/jit-probes.md`） |
| 2 | mock/打桩通过当真实通过 | 至少一条端到端断言打真实链路 |
| 3 | 局部绿当全局绿 | 全量回归，或声明确切未跑范围 |
| 4 | 文档/README 声明完成当验收 | 验收只认 L3 证据，不认叙述 |
| 5 | 「reviewer 说是预期行为」且无反驳依据 | 用差分判据：比基线多了谁的什么 |
| 6 | 只测 happy path（确认按钮） | 异常路径与边界至少各一条 |
