# ADR 模板

## 标题
精简的描述性标题

## 状态
`proposed` | `accepted` | `deprecated` | `superseded`

复验：`YYYY-MM-DD`（accepted 之日起 +12 个月；到期由 dj-gov 巡检提出复核，续用则刷新日期，失效则转 deprecated）

## 上下文
为什么需要这个决策？当前遇到了什么问题？

## 决策
我们做了什么选择？

### 替代方案（三态记录）
- **否决**：<方案> —— <一句话理由>
- **暂缓**：<方案> —— <复活条件：什么信号出现时重新评估>
- 未认真评估过的方案不列。

## 明确不做
本决策显式排除的范围。负向边界写进决策本身，防 scope creep；后续提案撞线时先读这里再发起。

## 影响
这个决策带来的正面和负面影响。

## 关联
- 相关的 ADR
- 关联的技能（dj-xxx）
- 关联的 PR / commit

---

## 规则

1. ADR 编号仅用作文件名前缀（`NNN-title.md`），不做层级嵌套
2. 已接受的 ADR 不再修改，只追加后续 ADR 来修正
3. 每个跨技能的设计决策都应有 ADR；结构性改动（技能拆分/合并/门禁变更）必配 ADR
4. ADR 由 `dijiang mem` 关联记忆
5. 复验日期到期由 dj-gov 知识治理巡检发现：继续有效则刷新复验日期，失效则改 `deprecated` 并注明替代者
