# 任务图并行：frontier、集成分支与 merger

> 摘要：工单不是步骤列表，是任务图——任何时刻都存在一批「阻塞项已清」的可领取票（frontier）。串行 blockers-first 只适合人手推；无人值守或票多时，按 frontier 并行派发，用独立集成分支收口。
>
> 来源：mattpocock/skills `implement-spec`（MIT）的并行编排；DiJiang 版复用既有 worktree 纪律与阻塞边。

## 什么时候用

| 条件 | 用串行（默认） | 用并行 frontier |
|---|---|---|
| 票数 | 1–3 张 | ≥4 张，且互不阻塞 |
| 人的在场 | 用户逐张推 | 无人值守 / 长任务 |
| 冲突面 | 票之间改同一文件 | 各票触及不同模块 |
| 验证成本 | 一次全量回归便宜 | 每票自带快速层，整支一次评审 |

## 三件套

### 1. frontier（可领取集合）

- 每张票在 `blocked_by` 里声明阻塞边（dj-split 已要求）；**frontier = 所有阻塞项已完成的票**。
- 每轮只派当前 frontier，不预先派「以后会解锁的票」——解锁前它的上下文可能已经变了。
- 一张票完成 → 重算 frontier → 再派。frontier 为空但票未全完 = 有环或死锁，停下报用户。

### 2. 集成分支（integration branch）

- 从任务基线建一条集成分支（`feat/<batch>`），每次派发前把它的 tip merge 进每张票的分支，保证 worker 起手就是最新集成态。
- worker 完成前也要求它先 merge 集成分支 tip，自己解冲突——冲突在票内解，不留给 merger 猜。
- 集成分支永远可跑：每合入一张票就跑一次快速层，红了立即停下，不叠下一张。

### 3. merger（独立收口者）

- 合入由**没写这张票的** agent 做（主 session 或独立子代理），职责只做三件：确认票分支基于最新集成 tip、跑快速层、写一行合入记录（票号 / commit / 快速层结果）。
- merger 不改票的代码；合入失败退回 worker，不现场即兴修。
- 全部票合入后，在集成分支上跑一次整支评审（dj-check 双轴），修复由一个全新 implementer 一次收口，不在评审分支上补丁套补丁。

## 与现有纪律的关系

| 现有机制 | 复用方式 |
|---|---|
| dj-split 阻塞边 | frontier 的唯一数据源，不另建依赖系统 |
| dj-implement worktree | 每票一个 worktree，集成分支作为 base |
| dj-regression-guard 快速层 | 每次合入跑一次，作为「集成态可跑」证据 |
| dj-channel worker 契约 | 每个 implementer 都注入契约，回报必须带 SHA 与命令 |
| dj-decision 决策日志 | 合入与重算 frontier 记一行，长任务可回溯 |

## 失败模式

| 触发 | 一线修复 | 兜底 |
|---|---|---|
| 票之间偷偷改同一文件 | 派发前跑一次文件所有权检查，冲突票串行 | 合并冲突反复 → 退回串行 |
| frontier 一直不空但没人能动 | 检查阻塞边是否有环 / 是否有票依赖已取消项 | 报用户裁决 |
| 集成分支红着继续合 | 立即停，回滚该次合入 | 集成态连续两次红 → 整支停，回主线串行 |
| merger 顺手改代码 | 明确只读 + 只合入；改动退回 worker | 记录为流程违规，后续换人 |

## 不做什么

- 不为并行而并行：票少、冲突面大、验证便宜时，串行更快也更可审计。
- 不引入新依赖系统：阻塞边、issue 状态、worktree 都是现成机制。
- 不让 worker 自己合入自己的票——那等于取消 merger。
