# Correct: 纠正防复发

## 职责

agent 反复犯同一类错 → 改**仓库结构**让下一个 agent 犯不了（非修单次 bug）。假设每个贡献者只看打开过的文件、抄最近例子、走最短路能编译。

分层：`dj-hunt` 修单次，本 skill 灭一类；`dj-evolve` 是文档层兜底；`dj-memory` corrections 是输入素材。

## 工作流

### 1. 挖错误类别

读近期 commits/reverts/评审意见/agent 指令/workaround 注释归类，**同类第二次发生才算 class**，单次是 noise。

### 2. 逐级强制（高→低）

1. **架构消除**：状态唯一 owner、任务唯一路径；藏内部让错误 import 失败；手同步列表换单一事实源；删会照抄的旧路径
2. **类型强制**：让坏状态写不出来；编译拦不住就加 lint/CI，错误信息点名替代方案；模式已普遍时只拦新增
3. **行为测试**：修掉『行为坏了还过、只改内部就挂』的测试
4. **文档/agent 规则（最后）**：只收判断类——agent 跳过时无任何东西会失败

### 3. 修复并证明

最高频 class 现在就修，**一类一个 commit**。新检查必须在真实历史错误上证明会失败；本地与 CI 同一命令。例外写违规行：原因+到期日+批准人。

### 4. 维护 rule table

agent 指令文件里维护表：每条规则 ↔ 什么强制它。用户再纠正：修错 + 加规则；**规则已存在却无强制 = 复发**，同一次改动内升级强制层。错误不可能再犯时删规则。

## 边界

- 不跳级——某层做不到时降级并说明，不静默换文档层顶替
- 只处理已发生 ≥2 次的 class（来源：纠正/revert/评审）
- rule table 每行强制者必须真实存在，未建成标『强制待建』，禁填『靠自觉』

## 失败模式

| 触发 | 一线修复 | 兜底 |
|---|---|---|
| 『class』是单次失误 | 回 `dj-hunt` 当次处理 | 记 `dj-memory`，第 2 次再开 |
| 仓库无 lint/CI | 类型走编译期，测试走本地钩子 | 表标『强制待建』+ 明示缺口 |
| 架构改造超授权 | 拆 `dj-split` 工单，本次落测试层 | 明示残余风险，不装已根治 |

## 反例

| ❌ | ✅ |
|---|---|
| 再写一遍『注意别犯 X』 | 升级到会在该错误上失败的检查 |
| rule table 填『靠自觉』 | 每行有机制层强制者 |
| 检查没在历史错误上验证 | 拿真实案例跑给用户看 |
