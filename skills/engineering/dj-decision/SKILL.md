# Decision: 可审计决策轨迹

## 职责

无人值守/长期/多阶段任务（人类走开后要回来信任结果的）保留可审计决策轨迹：追加式 TSV 日志 + 收尾对账 + 跨模型扫风险。由 `dj-ask` 路由带入。

## 工作流

### 1. 建日志

单个 TSV，一行一个决策点（cell 单行）。列：`ts`（ISO8601）｜`phase`｜`decision`（做了什么，一行）｜`why`（白话讲原因）｜`evidence`（**指针非散文**：commit SHA / PR 号 / `file:line` / 产物或截图路径）｜`result`（`tests green` / `reverted` / `INCONCLUSIVE` / `open`）。

填充示例（含 evidence 指针写法）见 `references/decision-log-template.tsv`。

记**决策点与检查点**，非每个动作：分叉的选择、单元完成及其验证结果、转向/回滚及其触发、阻塞浮出、门禁被修。loop 一轮一行，跳过琐碎与不言自明的。

### 2. 位置与提交

默认本地不提交：工作目录 `decisions.tsv`，多任务并行时 `.audit/<task-slug>.tsv`。仅当任务大到审查者需要轨迹才信结果时提交。

### 3. 审计对账（收尾前必做）

日志逐行对照实际发生的事：每行映射真实决策吗？evidence 可解析且证明所声称的吗？塑造了工作却没记的分叉/转向 → 补一行。**纠正日志，不是改故事**：只增不删，错误行用新行覆盖并附真实指针。

### 4. 跨模型扫风险

收尾前用**不同模型家族**的子代理扫日志与实际过程，标出用户该注意的：弱证据决策、跳过未证明的验证、事后看冒险的选择。回复末尾加 **Attention** 段列 flag（『无 flag』合法），非重做工作。

### 5. 回来播报（人离开后回来时）

假定用户只记得自己最后一条消息。播报不是流水账，是**让他能当场拍板**：

- **进展**：<100 字白话，说清「做完了什么、卡在哪」，不贴日志。
- **待拍板清单**：每个待决项约 30 字，包含四件东西——链接/位置、对用户的影响、证据、推荐选项。少一项就不是待拍板项，是提问。
- **完整性优先于字数**：宁可整段长一点，也不许为了压字数删项或缩水；「回复本身足以决定」是唯一标准。
- **不凑数**：没有待决项就明确说「无需拍板」，不编造问题假装严谨。
- 完结时附 Attention 段（第 4 步产物），两者顺序：先待拍板，后 Attention。

## 边界

- 证据三态（verified / not run / inconclusive）沿用 `dj-check` 的 evidence-gate，不自创口径
- 历史行只增不删——错了用覆盖行
- 记录与审计，不替用户决策

## 失败模式

| 触发 | 一线修复 | 兜底 |
|---|---|---|
| 决策点刷屏 | 收紧到「分叉/单元完成/回滚/阻塞」四类 | 按 phase 分文件 |
| 证据写成散文 | 改 `file:line` / SHA / 产物路径 | 指向可复现脚本 |
| 审计发现日志失真 | 补覆盖行，附真实指针 | 列出无法验证的行，不下结论 |

## 反例

| ❌ | ✅ |
|---|---|
| 事无巨细记每行 / 事后补写整段 | 决策点逐行随任务追加 |
| 改/删历史行 | 追加覆盖行 |
| 全量过程压给用户 | 决策日志 + Attention 段，只列风险 |
