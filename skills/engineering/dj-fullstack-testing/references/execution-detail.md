# dj-fullstack-testing 执行细节参考

本文件承载 dj-fullstack-testing 的深度执行细节。SKILL.md 只保留职责骨架与流程步骤名；执行对应步骤时读本节。

## 1. 功能枚举细节

### 1.3 交互入口枚举（漏测根源）
对每个页面组件文件提取：`@click/@submit/@change/@input`、`data-test` 标记、表单控件、弹窗/抽屉、条件渲染区域（v-if/v-show）、下拉/选择器、日期/时间选择器（含禁用日期与边界）、开关切换、链接跳转、右键/长按、拖拽、滚动/无限滚动、图表交互、键盘事件、复制粘贴导入导出、列排序。输出：`交互入口清单`（路由 | 组件 | 交互类型 | 元素标识 | 关联后端命令 | 优先级）。

### 1.4 异常路径（必选）
删除被引用记录、边界值输入（0/负数/超大/空/特殊字符）、弹窗可关闭、空状态、并发/重复提交、限流与配额、幂等/重放、契约/schema 变更、权限/未登录、搜索筛选、日期范围逻辑、分页/加载、网络异常、数据一致性冲突、文件上传异常、图表/大列表性能边界、404/错误页、注入载荷。输出：`异常路径清单`。

### 1.4a 业务场景（控件全绿 ≠ 流程能走通）
以业务流程为单位（非页面）：核心用户旅程、状态机迁移表、多角色数据隔离（API 直调验证，不能只靠前端隐藏按钮）。旅程级测试落 `tests/test_e2e_<scenario>.spec.ts`。

### 1.6a 枚举完整性交叉校验（强制）
对每个枚举类别用 grep 给独立计数，与清单条目数交叉比对。独立计数大于清单 → 枚举不完整，回补再生成，禁止进入下一步。结果写入枚举文档"交叉校验结果"节。

| 枚举类别 | 独立计数示例命令 | 比对对象 |
|---------|----------------|---------|
| 前端路由 | `grep -rE "path:\s*['\"]" src/router` | 路由清单行数 |
| 后端 API | `grep -rE "@app\.(get\|post\|put\|delete)\|#\[tauri::command\]" -r .` | 后端命令清单行数 |
| 交互入口 | `grep -rE "@click\|@submit\|@change\|onClick=" --include="*.vue" --include="*.tsx" -r src` | 交互入口清单行数 |

### 1.7 测试用例生成
可自动化 → `tests/`：`test_api_<module>.py` / `test_ui_<page>.spec.ts`，脚本头部注释 commit id + `# Covers: TC-xxx`。不可自动化 → `docs/test-cases/test-case-spec.md`（TC-xxx：触发方式/预期行为/测试方法/优先级）。同一功能点脚本与文档不重复定义，互相引用编号。

## 2. 后端分批执行

- 不要一次跑全量（Windows 全量 pytest 常超时、Rust 编译慢）
- **Web**：按文件分批 `pytest tests/api/test_api.py -q --tb=short`，每批 1-3 文件，`--timeout=30`
- **Rust**：`cargo test --lib commands::<module>` 每批一模块；集成测试单独跑；覆盖率 `cargo-llvm-cov`/`cargo-tarpaulin`
- **Cargo 发现陷阱**：`tests/` 子目录 `.rs` 不会自动发现，需 `Cargo.toml` 显式 `[[test]] name path`；执行前 `cargo test -- --list` 确认识别（注意需用 `--`），对比 `find tests/ -name '*.rs'` 查遗漏
- **双覆盖率指标**：`pytest --cov=<src> --cov-report=term`，分批用 `--cov-append`；清单覆盖度与代码覆盖率互为校验

## 3. 启动前后端

- **启动优先级（按 0.0 建档，不临时现拼）**：构建产物 → Makefile → package.json scripts → 框架特定命令兜底
- 后端 FastAPI 例：`NO_PROXY=127.0.0.1,localhost uvicorn app.main:app --host 127.0.0.1 --port 8010 --reload` + `curl --noproxy 127.0.0.1,localhost http://127.0.0.1:8010/health/live`
- 前端：`NO_PROXY=127.0.0.1,localhost npx vite --port 3020 --host 127.0.0.1 --strictPort`
- Tauri：`cargo tauri dev`；前端 `__TAURI_INTERNALS__.invoke()`；CDP：Android `adb forward tcp:9225`、macOS `--remote-debugging-port`
- **无设备降级**：无 CDP 时 Rust 走 cargo test，前端 UI 走 Playwright 访问 dev server（mock invoke 或跳过涉及命令的交互），报告标注 UI 层 SKIP 原因
- **mock 响应格式陷阱**：`invoke()` 响应须按组件实际期望格式（多数 `{status:'success',data}`），格式不匹配会误判 FAIL，截图走查确认真实渲染后再定性

**平台陷阱**：系统代理 127.0.0.1:12808 拦截 localhost → `--noproxy 127.0.0.1,localhost` 或 `NO_PROXY`；Windows httpx `trust_env=True` 拦截 → 显式 `trust_env=False`；长驻进程用 `screen`。

## 4. API 深度验证

- **4.2 契约/Schema（状态码 200 ≠ 契约没变）**：有 OpenAPI → `schemathesis run <url> --checks all` > pytest+jsonschema > curl+jq 兜底；必查文档漂移与隐性 schema 变更。无 OpenAPI → 首轮快照响应结构落盘 `docs/testing/api-schema-snapshot.json`，后续回归 diff。
- **4.3 状态码语义**：创建 201、删除 204/200 且 GET→404、参数错 400/422、未认证 401、权限不足 403（不混用）、不存在 404、业务拒绝 409/422。错误体统一结构。
- **4.4 限流与配额**：突发并发超限 → 429 + Retry-After；窗口重置恢复；低配不受污染。无设计则标安全建议。
- **4.5 幂等性**：重复 POST 不重复；Idempotency-Key 重放；PUT 中断重发状态一致；删除连发第 2 次 404 或幂等。
- **4.6 数据落盘**：关键写操作后回读确认真实落盘且字段一致；分页/排序/过滤边界优雅处理。

## 5. UI 验证

### 5.1 API 层
逐个调用功能清单后端命令，验证 CRUD + 边界值。

### 5.2 UI 交互层
逐页导航，每页验证矩阵：表单提交、弹窗确认/取消、删除流程、列表搜索筛选分页、Tab/切换、按钮跳转、条件渲染、下拉、开关、链接、拖拽、滚动加载、图表交互、键盘、复制导入导出、列排序。同时：
- 确定性视觉回归：核心页面 `toHaveScreenshot()` 像素基线（`tests/__screenshots__/`），回归 diff；UI 改版显式更新基线
- 截图走查兜底：无基线页面用 image_understanding
- 可访问性：axe-core 扫描，critical/serious 入缺陷
- 控制台 error/warning

### 5.3 UX 体验评估（控件能用 ≠ 体验好用）
按维度：状态可见性/错误体验/防错可撤销/一致性/效率/响应性/可访问性/信息架构/空态引导/移动端适配。输出 `UX 问题清单`（维度|页面|现象|建议|严重度），与功能缺陷分开统计。

### 5.4 数据与业务逻辑正确性（控件能用 ≠ 结果对）
- 列表/下拉：无重复，数量与去重后 DB 记录一致
- 计算/聚合：已知数据手工算预期值比对
- 筛选/搜索：结果集恰等于预期子集
- 日期/范围：禁用日期与业务规则一致
- CRUD：提交 + 落盘回读联动
- 有下游影响的写操作：核对库存/余额/关联记录同步变化

**多层次追踪**：核心写操作在 UI 反馈 → HTTP 响应 → 后端逻辑 → 数据库 → 下游 → 异步任务多层核对；只验证 UI"成功"就 PASS 是最大坑。

## 6. 覆盖度核对

逐项标注 ✅ PASS / ❌ FAIL / ⏭️ SKIP（说明原因）/ ⬜ MISSING（必须补测）。只验证"无报错"未比对结果的项目不能 PASS，标 SKIP 注明。

## 7. 报告结构

- 覆盖度总表 + 功能清单执行表
- API 深度验证结论（契约、状态码、限流、幂等、落盘）
- 业务逻辑校验清单（独立节，FAIL 可见预期 vs 实际差异）
- UX 问题清单（独立节，分开计数）
- 覆盖率双指标差异解释
- 视觉回归 + 可访问性结论
- 非功能测试结论（引用）
- 缺陷清单：标题/环境/前置/复现步骤/实际结果/预期结果/严重度/证据/定位/修复建议
- 发布建议：结合缺陷严重度 + 覆盖率 + 核心业务风险 → ✅/⚠️/❌

## 实战教训

- 列表/下拉大量重复选项 → 数量与去重后 DB 记录一致
- 汇总金额算错 → 已知测试数据手工比对
- 筛选结果含不匹配项 → 结果集应恰好等于预期子集
- 前端显示成功但字段被截断 → 与落盘回读联动
- 下单成功但库存没扣 → 下游影响多层核对
