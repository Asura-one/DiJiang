# CONTEXT 格式

```
## 项目
一句话
## 领域语言
- **术语**: 定义 _(Avoid: 别名1, 别名2)_
## 技术栈
- 语言: 版本
## 架构
简图或描述
```

## 领域语言节的三条纪律

1. **一个词只留一个正名**：同义说法写进 `_Avoid_` 括注作为禁用别名。语言压缩靠拍板一个词、其余显式列禁——只写「也叫 X」不构成压制，模型会继续混用。
2. **只收本项目特有的概念**：通用编程概念（超时、错误类型、工具函数模式）即使项目大量使用也不入表。入表标准是「新人必须知道、且与字面意思不同」。
3. **词表零实现细节**：定义写「是什么、与别的词什么关系」，不写怎么实现、不写参数与路径。实现细节属于设计文档，混进来词汇表会变成过期快照。

## 多上下文

一个仓库有多个限界上下文时，末尾加一张关系表，声明上下文之间是共享内核、上下游还是防腐层，避免同一个词在不同上下文被当成同一件事。

## 改名不自动做

`CONTEXT → GLOSSARY` 之类改名涉及 dj-ask/dj-hunt 等多处引用，属架构决策；本文件的纪律在现有文件名下可完整执行，不需要改名。
