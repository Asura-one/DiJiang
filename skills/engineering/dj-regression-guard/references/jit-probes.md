# JiT 探针：按 diff 定制的临时测试

> 摘要：S2.5 条件触发的一次性探针协议——改动触及无测试覆盖的新行为时，动态生成临时测试抓行为差异；与永久回归测试双线并存，弱捕获可收割为永久资产。

## 为什么需要

三明治的快速层是**既有测试的子集**：它只能证明「旧功能没被破坏」，无法证明「新行为是对的」。当 diff 落在测试覆盖的空白区，基线绿 + 回归绿会产生**假阴性绿灯**——什么都没测到，但一切看起来正常。

JiT 探针补的就是这条缝：按 diff 现场生成、双版本跑、用完即弃。

## 触发条件（S2.5 判定）

- diff 新增/修改的行为路径**不在**任何既有测试覆盖内（对照 diff 文件与快速层清单）
- diff 全程落在既有测试覆盖内 → 跳过（探针有生成成本，不为已覆盖的行为付）
- 拿不准覆盖与否 → 按未覆盖处理（宁可多一次探针）

## 探针协议（最小可执行核）

1. **生成**：按 diff 写一次性测试（探针），断言新行为的预期效果——期望来自规格/任务描述，不来自实现代码自证
2. **双版本跑**：改动前版本（parent）与改动后版本（diff）各跑一次探针
3. **判读**：
   - **parent 绿 / diff 红** → 改动破坏了预期行为，走 S4 处置
   - **parent 红 / diff 红** → 探针写错了或行为本来就有问题——人工看一眼是哪种
   - **parent 绿 / diff 绿** → 新行为符合预期，探针使命完成
4. **人答一句**：探针红时问用户「这是预期变化吗？」——是 → 更新探针断言（预期变了）；否 → 回归
5. **收割**：捕获到真实行为差异的探针，升级为永久回归测试进快速层候选；纯确认性的探针用完即删，不堆积

## 纪律

- 探针是**临时的**：不留残骸——或收割进永久测试，或删除，不长期保留「临时」文件
- 探针不断言实现细节（私有方法、内部状态），只断言可观察行为
- 每次改码探针数量有界（覆盖 diff 新行为即止），不为省事写大而全

## 与三明治的关系

- S2 专项验证管「改动生效」，S2.5 探针管「新行为正确」，S3 回归管「旧行为不坏」——三层各管一段
- 探针失败计入专项失败口径（改错了），不计回归口径
