# dj-regression-guard 协议细节

本文件承载三明治协议的扩展场景与配套记录。SKILL.md 保留协议主体；遇到零基建项目、技能边界争议或需要报告模板时读本节。

## 1. 零基建退路（项目没有测试套件时）

1. **基线退化**：S1 的快速层退化为冒烟级检查——服务能启动、健康检查端点返回 200、核心入口页面能打开（复用 `dj-fullstack-testing` 步骤 3a 的冒烟最小集）
2. **专项强制 TDD**：bug 修复必须先写失败测试——这个测试本身就是该模块的第一块测试资产
3. **模块级同步补全**：为本次任务涉及的模块生成测试（枚举该模块功能点 + 生成用例，参照 `dj-fullstack-testing` 步骤 1 的枚举方法，但范围仅限受影响模块）。全库级套件补全不做同步阻塞，记入测试债台账由后续任务逐步偿还
4. **复利效应**：每个任务沉淀的专项测试逐渐累积为该项目的回归套件，零基建项目随用随建

## 2. S5 全量层触发条件详情

- 触发条件：diff 触及 P0 范围——路由定义、依赖清单（package.json / Cargo.toml / requirements.txt）、公共工具库（src/utils / src/lib）、数据库 schema
- 建议话术需包含波及面证据（改了什么、按 `dj-fullstack-testing` 0.1a 映射影响哪些模块）
- 用户同意 → 转交 `dj-fullstack-testing` 执行全量模式；不同意 → 记录在任务报告，协议到此为止

## 3. 与其他技能的边界

| 技能 | 分工 |
|------|------|
| `dj-implement` / `dj-tdd` | 改码与红绿循环的执行者，本技能只做护送（基线/回归/归因），不接管改码 |
| `dj-hunt` | bug 排查与修复者。Hunt 定位根因后，修复的回归保护由本协议承接；反之本协议 S4 的"自动修复"归 hunt 纪律管 |
| `dj-fullstack-testing` | 全量回归引擎。本技能引用其三处机制：步骤 0.1a 的 diff→模块映射表、步骤 3a 的冒烟最小集、`docs/project-understanding.md` 文档格式。**引用不复制**——上述机制以 `dj-fullstack-testing` 文本为准，本技能不内嵌副本，其更新自动生效 |
| `dj-check` | 交付质量门禁（改码结束后）。与三明治协议互补：本协议护改码过程，dj-check 护交付收口 |

## 4. 任务报告要素（协议执行完毕后向用户汇报）

- 基线状态：commit-id、快速层构成、已知基线失败数
- 专项结果：红测转绿 / 验收通过与否
- 回归结果：新增失败数（应为 0）、flaky 项、顺带修复项
- 处置记录：若触发 S4，写明走到了哪一步
- 建议与欠账：S5 是否建议全量、S6 台账当前概览

## 5. 反例（禁止行为）全表

| # | 反模式 | 后果 |
|---|--------|------|
| 1 | 跳过 S1 基线，只做改后回归 | 改后失败无法区分"我改坏的"和"本来就坏的"，归因失效 |
| 2 | 绝对绿灯要求（基线红了拒绝改码） | 存量项目几乎必然死锁，协议被执行成本杀死 |
| 3 | 改测试让回归变绿 | 铁律违反。测试问题必须显式标记说明 |
| 4 | 任务内每次编辑都跑双回归 | 耗时翻倍拖垮迭代，粒度 = 逻辑任务级 |
| 5 | TDD 豁免三明治 | TDD 保证新功能有效，对回归是盲的，S3 一步不能省 |
| 6 | 专项和回归混跑、失败混报 | 两类失败归因不同，混报后修复方向不可判 |
| 7 | 基线快照持久化到 docs/ | 基线只服务本次任务，过期快照是噪音 |
| 8 | 零基建项目同步补全全库套件 | 修 bug 5 分钟、补套件 2 小时，agent 会悄悄绕过协议 |
## 6. flaky 判定与隔离（S4 第 2 步的语义细节；来源 fishzjp/qa-skills test-reliability）

三层不可混谈——**单条判定正确 ≠ 套件健康；套件全绿 ≠ 门禁证据合格**（可能全靠重试撑着）：

| 层 | 判定依据 | 结论边界 |
|----|---------|---------|
| 用例级 | **复跑矩阵**（同输入多次运行的结果序列），不是感觉 | 首跑红、原样重跑绿 = 定性为 flaky；重跑只用于定性，**不算通过** |
| 套件级 | flaky 率、隔离数、重试救回率 | 需要健康度数字，不接受"大概稳定" |
| 门禁级 | 重试绿 / 隔离跳过 / 未跑 各算什么 | 重试绿与隔离跳过都**不是发布证据**；关键卡点 flaky 必须显式上报 |

处置纪律：

- 短期 `skip`/`fixme` 标注 + 排期修根因，不做无限重试掩盖
- 同一 flaky 项连续两次任务命中 → 隔离修复（而不是每次重跑放行）
- flaky 根因四类粗分：等待/时序、测试间共享状态污染、外部依赖不稳定、随机数据——分类决定修法
- flaky 清单与判定跨轮追踪（测试债台账 `docs/testing/test-debt.md`），不因一次通过而消失


## 7. S0 快速层选法与超时降级（正文迁入）

"快速层" = 改前/改后双跑的测试子集，目标 < 3 分钟。按序判定：项目有冒烟标记（`@pytest.mark.smoke` 等）→ 跑标记子集；无标记 → 按 `dj-fullstack-testing` 0.1a 映射表圈受影响模块测试 + 3a 冒烟最小集；无测试基建 → 走零基建退路。选法持久化到 `docs/project-understanding.md`"快速层定义"节，基础设施文件变更时重判。首次接入的项目同时建 `CONSTRAINTS.md` 质量契约。

**超时降级**：S1 执行时快速层超 3 分钟 → 收窄为"冒烟最小集 + 直接触及模块测试"，记入基线快照（S3 跑同一子集保可比）；仍超时则保留并标注建议拆分，不阻塞。

## 8. S1 改前基线四步（正文迁入）

1. `git log -1 --format=%H` 记 commit-id
2. 跑快速层，快照落盘 `.temp/regression-baseline-<时间戳>.json`（commit-id、清单、逐项 PASS/FAIL、耗时）
3. **允许基线红**：已有失败记入"已知基线失败清单"，不阻断改码；比对用**增量对比**——只关心改后新增失败
4. 快照生命周期 = 本任务，结束即删

## 9. 改码执行与 TDD 分工细则（正文迁入）

改码入口照常走 `dj-implement` / `dj-tdd`，本技能不接管编码。**TDD 红测兼任专项测试**：bug 修复先写失败测试，功能新增先写验收测试。粒度 = 逻辑任务级：任务内多次编辑不重复跑回归，任务结束执行一次 S3。

## 10. S3 改后回归三步（正文迁入）

1. 校验 commit-id 与基线一致：中途有其他提交（基线过期）→ 重跑 S1
2. 重跑快速层，与基线逐项 diff：已知失败保持失败不算回归；**新增失败 → S4**；已知失败转绿 → 顺带修复记录（不放行条件）
3. **门禁自检**：`scripts/floor_guard.py --base <分支点>` 查五类「最便宜变绿」与契约缺命令行；exit 2 不得读作通过

## 11. S4 新增失败处置细则（正文迁入）

### 第 1 步：基线 diff 滤噪与 stash 甄别

1. **基线 diff 滤噪**：确认不在已知失败清单；基线缺失/过期时用 `git stash` 重跑**同一条命令、同一组测试**甄别存量（单跑/合跑不可比）。**只 stash 自己改动的文件**（`git stash push -- <path>`）——工作区有他人未提交改动时，全量 stash 回干净 HEAD 会把别人的改动一起抽走，「本来就坏」的现场消失、存量被误判成自己的回归。stash 循环被中断会把修改埋进 stash、后续 pop 按 LIFO 弹错条目**静默丢失修改**——中断后先 `git stash list` + `git status` 对账，pop 后 grep 标志行确认修改还在

### 第 2 步：flaky 重试

2. **flaky 重试 ×1**：单独重跑，过则标记 flaky 放行（连续两次任务同 flaky 项建议隔离修复）。**重跑只用于定性、不算通过**：flaky 项不得作为"回归已绿"证据，须记入测试债台账跨轮追踪；发布卡点的 flaky 不得静默放过

## 12. S5 全量层建议详情（正文迁入）

任务改动波及面大时（diff 触及路由/依赖清单/公共工具库/DB schema 的 P0 范围）主动建议跑全量，话术含波及面证据。**用户未答复前不得自行启动**；同意 → 转交 `dj-fullstack-testing`；不同意 → 记录后止。

## 13. S6 测试债台账（正文迁入）

走过零基建退路或补全不完整的任务，欠账记入 `docs/testing/test-debt.md`（模块 | 欠账 | 补全方式 | 日期）。台账非阻塞；任务触及欠账模块时顺带偿还；汇报时附测试债概览。

## 14. Gotchas 迁入条目（正文迁入；对应判据已保留在 SKILL.md 各步正文）

| 快照存 docs/ | 生命周期=本任务 |

| 混跑专项与回归 | 专项先行，回归后行 |

| stash 甄别存量被中断埋掉修改 | `git stash list` + `git status` 对账，pop 后验证标志行还在 |

| 脏工作区全量 stash 甄别（抽走他人未提交改动） | 只 stash 自己的文件：`git stash push -- <path>` |


## 15. S2 归因分离细则（正文迁入）

改码完成后**先跑专项再跑回归**：红测转绿/验收通过 = 改动生效；专项失败 = 改动没生效，回改码，此时**不要**跑 S3。专项挂 = 改错了；回归挂 = 改多了波及别处——两类失败归因分离，不得混报。
