# dj-regression-guard 协议细节

本文件承载三明治协议的扩展场景与配套记录。SKILL.md 保留协议主体；遇到零基建项目、技能边界争议或需要报告模板时读本节。

## 1. 零基建退路（项目没有测试套件时）

1. **基线退化**：S1 的快速层退化为冒烟级检查——服务能启动、健康检查端点返回 200、核心入口页面能打开（复用 `dj-fullstack-testing` 步骤 3a 的冒烟最小集）
2. **专项强制 TDD**：bug 修复必须先写失败测试——这个测试本身就是该模块的第一块测试资产
3. **模块级同步补全**：为本次任务涉及的模块生成测试（枚举该模块功能点 + 生成用例，参照 `dj-fullstack-testing` 步骤 1 的枚举方法，但范围仅限受影响模块）。全库级套件补全不做同步阻塞，记入测试债台账由后续任务逐步偿还
4. **复利效应**：每个任务沉淀的专项测试逐渐累积为该项目的回归套件，零基建项目随用随建

## 2. S5 全量层触发条件详情

- 触发条件：diff 触及 P0 范围——路由定义、依赖清单（package.json / Cargo.toml / requirements.txt）、公共工具库（src/utils / src/lib）、数据库 schema
- 建议话术需包含波及面证据（改了什么、按 `dj-fullstack-testing` 0.1a 映射影响哪些模块）
- 用户同意 → 转交 `dj-fullstack-testing` 执行全量模式；不同意 → 记录在任务报告，协议到此为止

## 3. 与其他技能的边界

| 技能 | 分工 |
|------|------|
| `dj-implement` / `dj-tdd` | 改码与红绿循环的执行者，本技能只做护送（基线/回归/归因），不接管改码 |
| `dj-hunt` | bug 排查与修复者。Hunt 定位根因后，修复的回归保护由本协议承接；反之本协议 S4 的"自动修复"归 hunt 纪律管 |
| `dj-fullstack-testing` | 全量回归引擎。本技能引用其三处机制：步骤 0.1a 的 diff→模块映射表、步骤 3a 的冒烟最小集、`docs/project-understanding.md` 文档格式。**引用不复制**——上述机制以 `dj-fullstack-testing` 文本为准，本技能不内嵌副本，其更新自动生效 |
| `dj-check` | 交付质量门禁（改码结束后）。与三明治协议互补：本协议护改码过程，dj-check 护交付收口 |

## 4. 任务报告要素（协议执行完毕后向用户汇报）

- 基线状态：commit-id、快速层构成、已知基线失败数
- 专项结果：红测转绿 / 验收通过与否
- 回归结果：新增失败数（应为 0）、flaky 项、顺带修复项
- 处置记录：若触发 S4，写明走到了哪一步
- 建议与欠账：S5 是否建议全量、S6 台账当前概览

## 5. 反例（禁止行为）全表

| # | 反模式 | 后果 |
|---|--------|------|
| 1 | 跳过 S1 基线，只做改后回归 | 改后失败无法区分"我改坏的"和"本来就坏的"，归因失效 |
| 2 | 绝对绿灯要求（基线红了拒绝改码） | 存量项目几乎必然死锁，协议被执行成本杀死 |
| 3 | 改测试让回归变绿 | 铁律违反。测试问题必须显式标记说明 |
| 4 | 任务内每次编辑都跑双回归 | 耗时翻倍拖垮迭代，粒度 = 逻辑任务级 |
| 5 | TDD 豁免三明治 | TDD 保证新功能有效，对回归是盲的，S3 一步不能省 |
| 6 | 专项和回归混跑、失败混报 | 两类失败归因不同，混报后修复方向不可判 |
| 7 | 基线快照持久化到 docs/ | 基线只服务本次任务，过期快照是噪音 |
| 8 | 零基建项目同步补全全库套件 | 修 bug 5 分钟、补套件 2 小时，agent 会悄悄绕过协议 |
