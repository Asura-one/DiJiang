# 召回手册（跨会话检索面）

> 由 dj-session-insight 并入（DJ-011）。何时召回 / 召回后处理的全量判据。

### 何时召回（跨会话判断）

召回是工具不是仪式。命中下表场景才召回，否则继续当前工作：

| 场景 | 触发线索 |
|------|---------|
| 脑暴重复风险 | 新 task 涉及之前讨论过的领域，先查是否有既得决定 |
| 熟悉 bug 调试 | 当前 bug 模式像之前修复过的 |
| 跨会话续接 | 用户隔了一段时间说「继续」 |
| 决策检索 | 用户提「关于 X 的决定」但决定在旧对话，不在 prd/spec 里 |
| 模式发现 | 用户问「我是不是一直在踩同一个坑」 |

**不召回**：当前上下文（已打开文件、当前对话、task 产物）已够用；问的是代码事实（grep/git log 更权威）；用户明说「不要翻历史」。

### 召回后处理

召回的原始记忆按现场判断落点，不预设单一目的地：

- **在回答中引用**——具体过往交换回答了当前问题，摘录并注明来源
- **更新 `<task>/prd.md` / `design.md`**——暴露了应记录的承重决策
- **更新 `.dijiang/spec/`**——属于项目级约定或 gotcha
- **仅内化**——一次性回忆，不写任何文件

把每次召回强制写入固定文件会让文件变成噪音。旧决策采信前对照当前代码与任务产物。
