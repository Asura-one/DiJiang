# Pattern Profile：重复结构与抽象机会扫描

> 摘要：dj-audit 第 4 档 profile——判「好」方向：找该抽未抽的结构重复，产出带迁移成本估算的抽象建议；与 default 档（判「该拆的」）互补镜像。原独立技能 dj-pattern 的精华按退役档案复活条件融合至此（2026-11-05）。

## 何时用本档

- 用户说「有没有重复代码 / 该不该抽公共函数 / 挖一下模式」——routing 已将「模式、重复、抽象、历史修复」指到本档
- 与 default 档的分工：default 问「这段抽象是不是不该存在（该拆）」，本档问「这些重复是不是该合（该抽）」——同一仓库两种视角，不混扫

## 三维扫描

### 1. 结构重复（主维度）

- 同构代码 / 类型定义 / 逻辑片段出现 **≥3 次**才构成模式；三次以下是正常相似，不报（防噪声——与 dj-evolve 复现门槛同构，域不同：那边挖 session 经验，这边挖 repo 结构）
- 报告必列**全部发现位置**（文件:行号），不凭印象描述
- 检测手法：grep 特征片段比对；仓库已有 jscpd 类工具则用工具，无则手动

### 2. 历史修复聚类

调用 `references/git-archaeology.md` 的五命令——bug 聚类 × 变更热点的交集即「同类 bug 反复修」模式，机制不在此重复。

### 3. 命名漂移（轻量）

同一领域概念多个命名（fetch/get/load 混用）。只收集现象清单，收敛方案协同 `dj-domain-modeling` 的重载词挑战，不在本档展开。

## 抽象建议门禁（五元组，缺一不报）

```text
模式：<描述>
证据：<出现位置 N 处——全列>
建议：<抽象方向：函数/模块/参数化——位置与边界>
成本：<约改动 M 处调用方>
价值：<消除重复 / 统一概念 / 缩小 bug 修复面>
```

## 纪律

- **先查镜像**：报抽象建议前先确认不是「已有抽象被绕过」——若调用方各自为政绕开了现成公共函数，正确建议是**收敛调用方**而不是建第二抽象（这正是 default 档会抓到的冗余）
- **疑似 vs 确定**：拿不准是否同一模式的标「疑似」（证据分级见 `docs/references/evidence-gate.md`）
- **只报告不修改**（dj-audit 红线）；抽象落地的实施走 `dj-implement`（受 `dj-regression-guard` 三明治护送，迁移成本在这步兑现验证）
