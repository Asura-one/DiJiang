# 审计实战手册：量化基线与执行纪律

> 摘要：dj-audit 扫描的实战执行层——六类信号的可量化判定、审计后的回归与文档联动；只报告不修改的红线不变。

## 量化基线（给"该不该报"一个数字）

| 信号类 | 量化判定 | 报告口径 |
|--------|---------|---------|
| 死依赖 | 依赖声明后 grep 零 import | 列依赖名 + 声明位置 |
| 死 CSS | 类名/选择器 grep 模板与代码零命中 | 列选择器 + 预估行数 |
| 非 repo 残留 | `git status --ignored` 清单里的生成物/残留 | 列文件 + 建议处置（gitignore 补录/删除） |
| 死代码 | 导出零引用、分支零可达 | 列符号 + **可删行数估计** |
| 过早抽象 | 单调用方接口 | 列接口 + 内联可省的层数 |
| 过大文件 | >300 行 | 列文件 + 拆分轴建议（按职责/按变更频率） |

**可删行数估计**是报告的汇总指标：审计产出不只是一堆问题，是"这轮审计能减多少行"的一个数。

## 判定陷阱

- **有 API 无调用方 ≠ 死代码**：先查是否被外部消费（公开库导出、动态分发、CLI 入口）——是则标「疑似接线缺失」，不是「删除」
- grep 前先读 `docs/references/anti-patterns.md` #26（去冗余不验载体）：删除建议必须验证别处无替代载体
- 测试文件里的"死代码"单独列：可能是测试基建的待补路径

## 审计后联动（报告的"下一步"节）

1. **修复优先级**：按"热点×聚类交集 > 高严重度 > 可删行数"排序
2. **文档同步提示**：删除/重构类建议落地时，按 `dj-gov` 联动 ADR/README/CHANGELOG 刷新——审计报告里预列将受影响的文档清单
3. **回归提示**：修复建议批量执行前走 `dj-regression-guard` 三明治——审计只报告，修复是另一个受保护的改码任务

## 边界重申

本手册是执行细化，不改变 dj-audit 红线：**只报告不修改**；修复动作回 dj-hunt/dj-implement。
