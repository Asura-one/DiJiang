# 覆盖台账与失败升级阶梯

> 摘要：跨轮 additive 覆盖记账（定位未审单元）、验证权与发现权分离、findings 三态、排查「无问题」结论的 L1-L7 升级阶梯。dj-fullstack-testing、dj-audit、dj-hunt 接入。

## 覆盖台账（additive ledger）

单轮审计/测试只覆盖总量的一部分（实测约一半）。没有台账，下一轮从零开始重复扫已审区域。

### 台账格式（Markdown，约定字段）

```markdown
| 单元 | 首审日期 | 状态 | 轮次备注 |
|------|---------|------|---------|
| payments/refund | 2026-11-05 | ✅ 审过，无发现 | 第 2 轮 |
| auth/login | 2026-11-05 | ❌ 未审 | 排队第 3 轮 |
```

### 纪律

1. **新轮只补缺口**：以台账未审单元为输入，不重扫 ✅ 单元——除非该单元本轮有 diff（diff 唤醒重扫）。
2. **验证权与发现权分离**：发现者不得自证自己的发现。验证交给独立通道（dj-check 的只报告不修、双人复查、或用户裁决）。防止「我发现的我确认」。
3. **findings 三态**：`confirmed`（L3 证据）/ `needs_validation`（待独立验证）/ `rejected`（验证后排除，保留一行记录）。禁止只有发现列表没有状态机。
4. **自检四项**：每单元审完自问——✅ 直接过 / ❌ 没过 / 变种试过没 / 关联单元查过没。只答前两项 = 覆盖未完成。

## 失败升级阶梯（L1-L7）

验证「无缺陷」类结论时，禁止在浅层排查后就下「没有问题」。**至少推进到 L4 才准说「没找到」**：

| 级 | 维度 | 动作 |
|----|------|------|
| L1 | 编码 | 直接原样请求/输入 |
| L2 | 变形 | 大小写、空白、URL 编码、注释、等价语法 |
| L3 | 逻辑 | 换等价业务路径触发同一功能 |
| L4 | 协议 | 换 HTTP 方法、Content-Type、版本头 |
| L5 | 入口 | 换端点/入口（内部 API、旧版本、移动端） |
| L6 | 组合 | 与其他功能/参数组合触发 |
| L7 | 时间 | 竞态、时序、重放、缓存过期 |

未到 L4 的「没问题」结论一律改写为「未充分排查」。
