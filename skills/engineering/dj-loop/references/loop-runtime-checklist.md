# Loop Runtime 上线检查清单

> 摘要：无人值守 loop 上线前（或 dj-loop Review 阶段）的九组检查——目标适配、触发、状态、gate、预算、权限、升级、可观测、退役。dj-loop 评审结论的证据底座。

逐组过，每项要能给出具体答案而不是「应该没问题」。

## 1. 目标与适配
- [ ] 目标写成可验证陈述（不是「保持健康」而是「依赖过期时开 PR」）
- [ ] 任务天然重复、有客观判据——一次性任务不值得 loop
- [ ] ROI 四条件量化过（loop-design.md）

## 2. 触发
- [ ] 触发源明确（cron/事件/心跳）且频率有上限
- [ ] 重入安全：上一轮未完成时新触发怎么办（跳过/排队/熔断）

## 3. 状态（Loop Run State）
- [ ] 状态外置落盘，崩溃后可从 state 恢复而非从零
- [ ] 字段只存下一轮要读的决策依据；过程叙事在 trace
- [ ] 并发保护：同一 loop 单实例或有锁

## 4. Objective Gate
- [ ] 每个产出至少一道强验证（evidence-gate.md）
- [ ] gate 定义固化在 spec 中，不随轮松
- [ ] 「拿掉 gate 还能自判完成吗」有答案——不能，则 gate 是正确性门，缺它不许上线

## 5. 预算
- [ ] 单轮 token/时间/调用上限
- [ ] 累计熔断点：连续失败 N 轮自动暂停
- [ ] 成本按 cost per accepted change 复盘

## 6. 权限与安全
- [ ] Action Surface 白名单化，最小权限
- [ ] 危险动作（删除/force push/对外发布）永远不自动化，升级给人
- [ ] 凭据不进 prompt/state；输出不含敏感信息

## 7. 升级与人工接管
- [ ] 失败升级路径明确：什么情况通知谁、格式是什么
- [ ] steering（打断当前轮）与 follow-up（追加到下轮）两类干预点有区分
- [ ] 副作用未确认的操作显式移交人，不自动重试

## 8. 可观测
- [ ] 每轮一行结构化摘要（时间/触发/结果/gate 结论/token）
- [ ] 失败原样传递（anti-patterns #23），禁止转述丢细节

## 9. 退役
- [ ] 有退役条件：连续 N 轮零 accepted change / 任务消失 / 维护成本超收益
- [ ] 退役动作：停触发 → 归档 spec 与台账 → 记录退役原因

> 通过标准：九组全部具体作答。任何一组只能答「应该没问题」，评审结论就是「不可托管」。
