# dj-hunt 假设纪律与实战案例

本文件承载 dj-hunt 的假设量化纪律细则、Gotchas 速查表与超长实战案例。SKILL.md 保留判定要点；排查陷阱速查、多候选根因取舍或遇到同类故障形态时读本节。

## 1. 假设优先级与置信度门禁（多候选根因的量化纪律）

1. **先验分配** — 按第一直觉给各假设分配概率（总和 100%），写下理由
2. **证据分级** — 可靠性从高到低：test output > 日志 > 用户报告 > 直觉。只让高可靠证据改变概率
3. **区分性证据优先** — 问"若 H1 真而 H3 假，我会看到什么？"——找能把两个假设分开的证据，而不是对谁都成立的证据
4. **置信度门禁**：

| 置信度 | 动作 |
|---|---|
| ≥90% | 直接修复，附 fallback 计划 |
| 70-90% | 修复，同时准备回退路径 |
| 50-70% | 先加探针验证假设，再决定修不修 |
| <50% | 继续收集证据，不许猜着修 |

先验不是承诺：证据更新后概率必须跟着动，警惕锚定在第一个可疑点。

## 2. Gotchas 速查表

| Gotcha | 预防 |
|---|---|
| 没确认复现就改 | 先建反馈环 |
| 一次改太多可能原因 | 一次一个改动 |
| 修完不验证 | 跑全量测试或冒烟 |
| 不确认 root cause 就改 | 先确认再改 |
| 存量失败未甄别 | 干净基线对比区分存量/新引入 |
| 多原因只修一个 | 重跑反馈环，列候选清单逐个验证 |
| 静默降级无标记 | fallback 显式标记，不注入 preferred 专属参数 |
| 生成字段未消费 | 审查输出字段提取代码；token 超耗优先排查 |
| 防护只在降级路径 | 预算/截断/校验全路径执行 |
| 服务端验证通过但用户端仍复现 | 验证层级对齐症状层级：浏览器症状在真实浏览器 network 复验（实际请求 URL/加载的资源 hash），中间层（缓存/代理/端口占用者）逐层排除 |

## 3. 实战案例（高价值 Gotcha 详情）

### 多个重叠原因叠加
多原因叠导致同一症状，只修一个其余仍在，bug 不消失。实测案例：SwiftUI ScrollView 高度为 0 有 4 个叠加原因（safeAreaInset 吃高度 + 缺 minHeight + tableHeader 占固定高度 + isFocused 动画触发重布局），只修第 1 个症状仍在。**修复后必须重跑反馈环确认症状消失；若症状仍在，继续排查其他候选原因，不要假设单一根因，列候选清单逐个验证。**

### 静默降级无标记
preferred 选项不存在时代码静默 fallback 到随机/默认值，无显式标记，导致配置与运行时割裂（如配了 worker A 实际跑 worker B + model 错配 provider）。**fallback 路径必须显式标记（返回 fallback 标志/记日志），且 fallback 时不注入 preferred 选项的专属参数。**

### 功能已生成但未消费
prompt 要求 LLM 生成某字段（如 structured_report），但输出解析代码不提取该字段，LLM 白耗 output token 生成后被丢弃。**审查 prompt 要求的每个输出字段是否都有对应的提取/消费代码；token 异常超耗时优先排查"生成但未消费"的字段。**

### 防护只在降级路径执行
预算/截断/校验机制只在错误/降级路径触发，正常路径无防护，导致正常路径 token/资源不受控。**预算/截断/校验必须在所有路径执行，不能只在 fallback 分支调用。**

### 验证层级与症状层级不一致（服务端已修、用户端仍坏）
修复本身正确，但验证在服务端（curl 200 + 新内容）做，症状出现在浏览器——中间层让验证失效。实测案例：SPA 登录报 `Unexpected token '<' ... is not valid JSON`（期待 JSON 收到 HTML），三层叠加：① 镜像内 dist 是旧构建（登录请求不带 `/api` 前缀，落到 SPA 静态回退，返回 200+HTML，`resp.json()` 崩）；② 换新镜像后浏览器仍加载旧 bundle（index.html 无 Cache-Control，被启发式缓存数小时）；③ 运行时 daemon 重启把旧栈拉起抢占了端口（响应出现陌生 bundle hash）。**规则：症状在哪一层出现，验证就在哪一层做——浏览器症状必须看浏览器 network 面板实际发出的请求 URL 与实际加载的资源 hash；「已验证修复」被用户复报时，枚举验证点与用户之间的每一层（浏览器缓存、代理、扩展、DNS、端口占用者）逐层排除。** 快速启发：前端 `Unexpected token '<'` = JSON 请求拿到 HTML = 路径没进 API 路由，先看实际请求 URL。
