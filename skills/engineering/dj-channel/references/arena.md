# arena: 多候选竞争择优 + 嫁接

来源：pstack arena 融合（2026-11）。dj-channel「独立共享」模式的升级档：**同一任务造 N 个候选，选基后把落选者的强点嫁进去**——适用于一次尝试就可能锁死错误形状的非平凡产物（设计方案、复杂实现、技术选型）。一次尝试有把握就用普通模式，不要滥用。

## 六阶段（Frame → 并发 → 交叉评审 → 选基 → 嫁接 → 验证）

1. **Frame**：所有候选拿同一 prompt（prompt 就是契约）。先写评分规则（3-6 条本任务可判分标准）——这是后面选基的尺子。每候选独立输出位（worktree 优先，否则临时目录），防写冲突
2. **并发**：一轮 spawn N 个候选，各自产工件 + 短理由（考虑过哪些替代、拒绝了什么）。候选没产出 → N-1 继续，记录掉队
3. **交叉评审**：spawn 一个**只读评审**子代理（与干活 agent 不同的模型家族优先，拿不到就标注自评），按评分规则逐条打分 + 推荐基座与理由；与主 agent 的阅读并行
4. **选基**：主 agent 逐个通读每个候选（不 skim），逐条对评分规则打分，与评审比对——一致 = 确认，分歧 = 一方有偏差或规则含糊，读双方理由再裁。**选未来维护者最能无痛扩展的那个**；平手选边界更干净/接口更小的
5. **嫁接**：把落选者值得移植的点（通常每候选 1-2 个，不是大部分）**手工折进**基座——按统一心智模型重新消化，不机械拼贴。候选们收敛到同一形状 = 强共识，直接用共识形状不嫁接；剧烈发散 = Frame 阶段没写清楚规格，回炉 reframe 重跑，**不平均分歧**
6. **验证**：对合成产物按 dj-check 证据门正常验证。验证抓到 arena 都漏掉的问题 → 要么 Frame 错了（reframe 重跑）要么嫁接时漏了精选（回第 5 步），不打补丁糊弄

## 输出

一个合成工件 + 简短合成说明（基座是谁为何、评审结论或注明跳过、每个嫁接点来源、拒绝了什么为何、收敛/掉队情况、验证结果）。

## 红线

- 评分规则在并发 spawn **之前**定，不许事后改尺子
- 先通读后选基——只看评审报告不读原文 = 弃权
- 「no findings」「全部没用上」都是合法结果，不硬嫁接凑数
