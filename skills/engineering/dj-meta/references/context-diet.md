# Context Diet：agent 指令层瘦身 Runbook

> 每轮注入的指令内容是稀缺资源；臃肿多半不是写多了，而是放错了层。模型升级、skill 数量明显增长、或发现 agent 复读无效指令时，对指令层重跑一次本流程。
>
> 首跑实测（2026-11-18，DiJiang 43 skill）：description 14,801 → 4,888 字符（-67%），删根 CLAUDE.md 1,570 字符，机械守卫基线不变（PASS 138 / WARN 24 / FAIL 0，突变测试 9/9）。

## 13 步流程

1. **盘点分层**：量化每轮注入层（根 AGENTS.md/CLAUDE.md、全局规则、无 `paths:` 的 rules、每个 skill 的 description）与按需加载层（SKILL.md 正文、references、docs）各占多少字符。
2. **分类出清单**：逐段标 修/删/挪/改写/保留；挪的写明目的地；每条附一句原因；清单先给用户确认再动手。
3. **逐句行为判断**：删一句话前问"删掉后 agent 行为会不会变"。"先读再改/跑测试/注意边界"这类本来就会做的——删。拿不准先保留。
4. **目标导向**：写目标（做完什么样、怎么算完成、要什么证据），少写实现路线。步骤删掉后还能换条路达成同样结果就删；只有顺序本身是约束才留（先验证再发布、先确认再删除）。
5. **重复合并**：同一要求说三遍 → 换成一个 agent 本来就懂的词；口号换成形象词，配一组 NO/OK 例子。
6. **内容归位**：需要判断的进 skill；同样输入总出同样输出的改成脚本或 hook；项目命令/发布步骤进项目指南；跨项目硬约束才进全局规则；"做 Y 前先读 X"改成"做 Y 时由 hook 注入 X"。
7. **描述三要素**：description 只写 做什么/什么时候用/不用于什么；近义词进触发词；只有部分场景用到的内容进 references。删技能前看真实调用记录，不要只 grep 名字；待删清单先展示。
8. **保护清单（永不动）**：用户偏好、被否掉的方案+原因、机器环境；不报错的坑与"看着像出错其实正常"的现象；不可逆操作规则（删数据/花钱/发布/提权/改写已推送历史）；带日期的拍板决策记录。
9. **先移后压**：先整行搬到按需加载文件再压缩；不边搬边改写；不可逆规则原样整段搬。
10. **落位技巧**：常触发规则（提交/发布/回复/删除）留根目录；挪进 docs/ 的在根目录留一句何时去读；根目录避免同时放 CLAUDE.md（Claude Code 有了它就跳过 AGENTS.md）；项目里重复全局规则的句子，只有所有在用工具都读全局规则时才删。
11. **自查**：`paths:` glob 都能匹配真实文件；grep 拆走的旧文件名；列出所有消失的行，逐行对上用户确认过的清单。机械列举用本技能 `scripts/check_moved_lines.py <base-rev>`（整行搬到任一指令文件即算保留，标题与标记不计数，exit 0 干净 / 1 有缺失 / 2 跑不了——2 不得读作通过）；已提交的瘦身用 `--head <prune-rev>` 事后审计。
12. **独立复查**：交给没参与精简的 agent——只给 `check_moved_lines.py` 的缺失行清单和仓库，不给结论；让它搜关键名词（非整句）；意思在哪都找不到的原样恢复。瘦身已提交后再复查时，一条一条对 `--head` 输出逐 commit 跑。
13. **加载验证**：新文件埋暗号，开新会话先读匹配文件再问暗号，再读不匹配文件做反向对照。

## 实测坑（首跑踩过，勿重蹈）

- **触发词不能从 description 挪走**：它是路由锚点 + 机械守卫（jaccard 触发词重叠检测）的数据源；挪到 `when_to_use` 后守卫提取为空 → 全部跳过 → 假绿。真正可删的是与中文描述重复表达的英文 "Use when..." 从句（43 处约 8.4k 字符）。
- **"不用于 X" 负向边界最易被误删**：独立复查实测抓回 dj-read 的 "Not for local text files already in the repo"——全库无等价物，属描述三要素之一，必须保留。
- **脚本改 frontmatter 必须写回整文件**：只写正则匹配片段会吃掉 `---`/`name:` 行（实测毁掉 2 个 skill 的 frontmatter，机械守卫当场咬出 FAIL 4）；正确做法是 `t[:m.start()] + new + t[m.end():]` 后写回全文，改完立即跑守卫对基线。
- **改守卫契约要同步模板**：删掉 "Use when" 强制校验后，skill-template 的模板行与警告行必须同步改，否则新技能又按旧契约写。
