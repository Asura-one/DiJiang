# 升格判据细化：阴性知识、复现门槛与候选字段

> 摘要：dj-evolve 判据筛选与候选展示的细化规则——阴性知识挖掘、复现门槛、反例与停止条件必填、存量体检。权威判据仍在 SCOPE.md，本文只做执行细化。

## 1. 阴性知识作为升格原料（第五类挖掘信号）

- 扫描候选时**必须查** `.dijiang/memory/` 中 `kind=negative` 的条目：死路、失败尝试、被否决的路线——失败经验的复利常高于成功经验。
- **分层纪律**：死路本体留记忆层（它描述「这个世界是什么样」）；技能层只升格「如何避免」的可操作规避（它描述「下次怎么做」）。例：记忆存「方案 X 在 exFAT 上必挂」，技能升格的是「构建前查文件系统支持符号链接」。
- 与 SCOPE「只增不删」的张力处理：记忆层阴性条目永不回滚（历史事实）；技能层不为死路建条目——只写规避。

## 2. 复现门槛（防单例噪音）

- 单次出现的经验**不提候选**，暂存 dj-memory 标待验证。
- 同一模式**第二次复现**才允许提候选（参考实践：momo-code 同一模式 ≥3 次才提炼 tactic——次数是设计选择不是普适值，取精神不取数）。
- 例外：带强证据的纠正（用户显式纠正 + 机制清晰可复述）可首现提候选，但必须标注「单例 + 强证据」。

## 3. 候选必带字段（行为合同）

每个候选展示时四字段齐全，缺一不提案：

| 字段 | 回答什么 |
|------|---------|
| 反例 | 这条规则的适用性何时失效？（边界情形） |
| 停止条件 | 什么信号出现时该放弃这条规则、交还人工？ |
| 复现次数 | 第几次出现？（单例需补强证据说明） |
| why | 规则存在的理由——缺 why 的规则是自进化时代第一批被「聪明」放宽的承重墙（anti-patterns #24） |

## 4. 验证纪律补充

- **验证集过拟合**：behavior-cases 通过数上升但真实会话表现无变化 → 怀疑案例集被候选「应试」，补真实场景案例再验。
- **致胜工具归因**：候选捆绑多个改动时只认最终致胜的那个——「常出现」≠「有贡献」，无法归因就拆成单候选。

## 5. 存量体检（skill-doctor）

dj-evolve 常规轮次之外，可对单一技能做健康体检——**只看失败会话**（成功会话无信息量）：

- 收集该技能近 N 次触发中未命中/路由错/执行失败的会话
- 三维评分：触发精度（误路由率）/ 执行质量（失败率）/ 覆盖完整（description 承诺 vs 实际做到）
- 产出：修补候选（走常规差分流程）或退役提案（走 SCOPE 退役政策）
