# PR/分支审查档（双轴纪律）

> 由 dj-review 并入（DJ-013）。check 第 5 档内核——两个独立维度分别审查后汇总，防互相污染。

## 双轴定义

- **轴 A — Spec 匹配度**：diff 是否忠实实现源需求（PRD/issue/spec）。报告遗漏的行为、超出范围的新增、与 spec 矛盾的设计
- **轴 B — 代码质量**：diff 内部质量。与项目现有模式的偏差、过度工程/过早抽象、潜在缺陷（空指针/资源泄漏/并发）、风格不一致

两轴输入与发现**保持独立**——子任务不互相引用，各自汇报。平台有并行执行能力时并行跑两轴；没有时串行，但不得因缺工具省略任一维度。

## 流程

1. 准备：`git diff --stat HEAD` + `git log --oneline -5`，确认变更范围与 PRD/issue 引用
2. 独立审查（两轴分别执行，只输出问题清单不修改代码）
3. 汇总为一份报告（模板见下）

## 汇总模板

```text
## 审查：<变更描述>
- Spec 匹配度：<通过/有问题>
- 代码质量：<通过/需改进>
- 安全性：<人工审阅重点，如涉及>
- 问题汇总：
  1. [严重] <问题描述>（来自：Spec/质量）
  2. [中等] <问题描述>
  3. [建议] <问题描述>
- 结论：<通过 / 需修改 / 需重新审查>
```

## 边界

- 不做深度架构评审——那是 `dj-pattern` / `dj-reason` 的职责范围
- 不引入 reviewer 自己的风格偏好——按项目现有模式判断
- 报问题必附建议方向——只报问题不改建议，reviewer 就没有价值

## 判例

| 情形 | 处置 |
|---|---|
| 无 PRD/issue 可对照 | 标注「无源可对照」，只跑质量轴 |
| 变更过大一次审不完 | 按文件/模块分批审，标未审范围 |
| spec 与实现严重冲突 | 报告冲突点，请用户裁决，不改码 |
