把用户无法独自回答的东西变成**问卷**：一个 Markdown 文档，交给一个人异步填写，或在会议上一起填写。接收者持有用户缺乏的知识；问卷把它拉出来。

**拷问发送，不拷问主题。** 只对用户拷问 _发送_（他们总能回答）：问卷给谁，你需要什么回来。文档中的问题然后对准接收者知道的和用户需要的**差距**。

1. **发给谁？** 一次交流问清接收者的角色、专长、与用户的关系。这决定问卷语气和上下文承载量。知道接收者是谁、他们知道什么用户不知道的，完成。

2. **你需要什么回来？** 一次交流问清产出：决定？批准？建议？评价？偏好？设一个明确的"完成"信号。

3. **起草文档。** 在文档中，问针对差距的问题（不是给用户的问题）。按你的发现组织问卷：语气、上下文承载量、邀请封面、渐进式问题顺序。目标：让接收者没有困惑地完成。

4. **检查发送。** 向用户展示，确认符合他们给的约束：目标、返回内容、语气。用户批准后交付。

## 结构

```markdown
# <主题> 问卷

你好 <接收者>，

<上下文：为什么请你填、背景是什么（按步骤 1 决定多少）>

## 问题

1. **问题标题** — 问题正文
2. ...
```

## 规则

- [ ] 一次交流问清"发给谁"
- [ ] 一次交流问清"你需要什么回来"
- [ ] 问题对准知识差距，不对准用户已有信息
- [ ] 文档组织方式让接收者没有把地完成
- [ ] 发送前展示给用户确认
